# Проект «Мини-Склад» (Главы 1–6)
Учебная конфигурация 1С:Предприятие 8.5 с контуром складского и управленческого учёта.

### Что внутри:
* **Подсистема:** Мини-Склад
* **Справочники:** Товары, Контрагенты
* **Документы:** Поступление, Реализация
* **Регистры:** Остатки товаров (партионный учёт прихода и расхода), Продажи (оборотный регистр)
* **Роли:** Администратор, Директор, Менеджер, Кладовщик, Бухгалтер
* **Интеграция:** HTTP-сервис `ОбменТоварами` (`/exchange/products`) и обработка `ИмитацияОбменаJSON`

### Как открыть:
1. Создайте пустую информационную базу в 1С.
2. Откройте её в режиме Конфигуратора.
3. Нажмите **Конфигурация -> Загрузить конфигурацию из файлов...** и выберите папку `src` из этого репозитория.
4. Нажмите **F7** для обновления базы данных.

### Неделя 2
* Разработан аналитический отчет «Обороты по товарам» на базе СКД.
* Создана печатная форма накладной для документа «Реализация».
* Выполнен аудит и траблшутинг интеграционного модуля КБ99 в среде УТ 11.5.

### Неделя 3
* Внедрено автоматическое списание себестоимости по партиям закупки из регистра остатков `ОстаткиТоваров` (ФИФО).
* Документ «Реализация» списывает остатки и фиксирует объемы продаж в оборотном регистре `Продажи`.
* Отчет «Обороты по товарам» переведен на таблицу `ОстаткиИОбороты` и настроен в виде дерева (Товар -> Партия) для анализа партий закупки.

### Неделя 4
* Добавлен механизм множественного подбора товаров в документах «Реализация» и «Поступление» (через передачу параметров формы выбора на клиенте).
* Реализован автоматический расчет сумм строк в табличных частях документов при изменении цены или количества.
* Настроено условное оформление списков: непроведенные документы визуально выделяются фиолетовым цветом.
* Реализован контроль заполнения ключевых реквизитов (Контрагент, Товар, Количество) со значением «Выдавать ошибку».
* Исправлен отчет по остаткам: осуществлен переход с таблицы `ОстаткиИОбороты` на виртуальную таблицу `Остатки` с ограничением периода на конец дня (`КонецПериода(&ДатаОтчета, "ДЕНЬ")`) и выводом точной даты партии.

### Неделя 5: Права доступа и регламентные задания
* **Ролевая модель (5 ролей):** настроено разграничение прав для ролей `Администратор`, `Директор`, `Бухгалтер`, `Менеджер` и `Кладовщик`.
* **Пользователи:** заведены учетные записи с демонстрацией объединения ролей (пользователю «Бухгалтер» назначены роли `Бухгалтер`, `Менеджер` и `Кладовщик`).
* **Регламентные задания:** создан серверный общий модуль `РегламентныеПроцедуры` и настроены фоновые задания `ОбновлениеИндекса` и `СлияниеИндекса` для полнотекстового поиска.
* **Интерфейс:** реализованы формы подбора товаров и условное оформление списков.

### Неделя 6: Обмен данными (JSON / HTTP-сервис)
* **HTTP-сервис `ОбменТоварами`** (корневой URL `exchange`, шаблон `/products`): реализованы методы `GET` (выдача остатков товаров в JSON) и `POST` (приём новых товаров из JSON с проверкой на дубли).
* **Обработка `ИмитацияОбменаJSON`:** создана управляемая форма для интерактивного тестирования приёма и выдачи JSON-пакетов в клиент-серверном контуре.
